# TrajCert Pre-Experiment Audit Matrix
**Exact requirement count: 250**
**Purpose:** executable pre-experiment verification specification for deciding whether TrajCert is scientifically and technically ready to begin its declared experiment campaign. This file is an audit matrix only; it does **not** record audit results and must not be treated as evidence that any requirement currently passes.
**Generation basis:** the complete authoritative TrajCert roadmap supplied for this task. Repository source inspection was not available to the matrix author, so roadmap-defined public CLI and experiment identities are named exactly, while implementation file/class/function names must be discovered from the current repository when this matrix is executed. Equivalent implementation architecture is acceptable when the scientific contract and wiring are preserved.
**Hard pre-experiment boundary:** do not execute any `trajcert run ...` scientific experiment while executing this audit. The only executable scientific-adjacent workflow permitted is the dedicated lightweight `trajcert smoke` contract, plus safe short commands and real production preprocessing. No development, confirmatory, robustness, generalization, failure-boundary, diagnostic, scaling, or synthesis experiment may be run.
## Authority hierarchy
- **Scientifically authoritative:** formulas; mathematical/algorithmic semantics; information-flow restrictions; chronology and leakage rules; experiment design; methods/comparators; condition grids; metrics; statistical procedures and units; seed roles; significance/equivalence/materiality logic; multiplicity; claim criteria; and failure/downscope semantics.
- **Empirically amendable:** measured raw-file structure, row/entity counts, eligible cohorts, available fields/classes, usable ranges, observed support, runtime/resource properties, and secondary-source availability. Differences require evidence-backed empirical deviation records; code/data must not be manipulated merely to reproduce obsolete expectations.
- **Implementation-flexible:** filenames, module boundaries, helper placement, class names, internal patterns, library choice, caching details, and parallelization strategy. Audit semantic equivalence, ownership, and wiring rather than visual similarity to the roadmap tree.
## Audit status and severity
Allowed `Status` values during execution: `PASS`, `FAIL`, `PARTIAL`, `MISSING`, `UNWIRED`, `DEAD_CODE_CANDIDATE`, `JUSTIFIED_EMPIRICAL_DEVIATION`, `JUSTIFIED_ARCHITECTURE_DEVIATION`, `BLOCKED_BY_PRE_EXPERIMENT_STATE`, `NOT_APPLICABLE`.

Severity values: `BLOCKER` prevents the pre-experiment gate; `MAJOR` is a material scientific/technical readiness defect that must be resolved or explicitly justified before the gate; `MINOR` is a non-blocking quality defect unless it masks a scientific issue. Matrix `Status` and `Finding / Action` cells are intentionally blank until the audit is executed.
## Required audit execution order
1. Read the complete authoritative roadmap and this matrix.
2. Inspect the current repository and inventory actual production source, tests, configuration, outputs/results layout, dependencies, and entry points.
3. Inventory the actual public CLI and reconcile it with the roadmap-defined `trajcert` interface without inventing commands or flags.
4. Generate a fresh Graphify analysis from the current working tree.
5. Construct the callable inventory and command/experiment call-graph closures.
6. Audit scientific contracts and scope boundaries.
7. Audit formula-by-formula mathematics and numerical conventions.
8. Audit data, chronology, preprocessing, eligibility, censoring, and leakage prevention.
9. Audit every experiment contract prospectively without running the experiment.
10. Audit every metric and statistical procedure at formula/unit/aggregation level.
11. Audit types, enums, primitive leaks, wrappers/conversions, and domain modelling.
12. Audit duplication, architecture, constants/defaults, paths, dead/unwired code, library opportunities, logging, and determinism.
13. Audit artifact identity, caching/reuse, invalidation, provenance, outputs/results separation, figures/tables, and reporting.
14. Remediate all identified implementation problems; preserve scientifically relevant code by wiring it before considering deletion.
15. Generate a second fresh Graphify analysis after remediation.
16. Run static/type/architecture quality checks.
17. Run the relevant deterministic/unit/integration/e2e tests; do not run experiment-scale workloads as tests.
18. Run all safe short/non-experiment CLI commands individually.
19. Run real production preprocessing against the actually available current-plan sources.
20. Rerun preprocessing to verify deterministic/idempotent reuse and stale-input behavior.
21. Perform a final fresh audit against every matrix row and close every BLOCKER/MAJOR finding.
22. Stop before any scientific `trajcert run ...` experiment execution.
